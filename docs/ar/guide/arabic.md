# دعم اللغة العربية

ما تفعله الحزمة للمستندات العربية، والأدوات التي تستطيع استخدامها في أي مكان من تطبيقك: الأرقام العربية أو اللاتينية، والحفاظ على ترتيب الرموز وأرقام الهواتف، والتفقيط (المبلغ كتابةً)، والتاريخ الهجري.

## ما الذي تغيّره `->locale('ar')` {#locale}

```php
use BiztechEG\EasyPdfWord\Facades\Doc;

Doc::template('invoice', $data)->locale('ar')->pdf();
```

استدعاء واحد يحدد ثلاثة أشياء:

- **الاتجاه.** يُرتَّب المستند من اليمين إلى اليسار: النص والجداول ورأس الصفحة وتذييلها. وتحصل ملفات Word على فقرات وجداول من اليمين إلى اليسار، ويُعلَّم النص العربي بأنه عربي ليختار Word الخط والحجم المناسبين.
- **الخط.** تستخدم المستندات التي تُكتب من اليمين إلى اليسار الخط `fonts.default` من ملف الإعدادات (Cairo)، وتستخدم غيرها `fonts.default_ltr` (Cairo أيضًا). وغيّره لكل مستند بـ `->font()`؛ انظر [الخطوط](/ar/guide/fonts).
- **التسميات.** تقرأ القوالب تسمياتها من `lang/ar.php` في مجلد القالب (فاتورة ضريبية، الإجمالي ...). والتسمية الناقصة هناك تُؤخذ من `lang/en.php`.

يتولى المحرك وصل الحروف العربية (تشكيلها): يفعل ذلك mPDF وChrome كلاهما، ويفعله Word بنفسه.

اللغات أسماء مثل `ar` و`en` و`ar_EG` و`ar-SA` و`zh-Hant-TW`. وتجعل `ar_EG` لغة النص العربي في ملفات Word العربية (مصر)، بينما تستخدم `ar` وحدها العربية (السعودية). وأي قيمة ليست اسم لغة، كالمسار، ترمي `InvalidArgumentException`.

بدون `->locale()` يستخدم المستند `locale` من `config/easy-pdf-word.php`، وحين تكون `null` (القيمة الافتراضية) يستخدم لغة التطبيق الحالية `app()->getLocale()`. فالـ middleware الذي يحدد اللغة لكل مستخدم يحدد كذلك لغة مستنداته.

### اللغات التي تُكتب من اليمين إلى اليسار {#rtl-languages}

هذه اللغات تجعل المستند من اليمين إلى اليسار: العربية (`ar`)، والآرامية (`arc`)، والكردية السورانية (`ckb`)، والديفيهية (`dv`)، والفارسية (`fa`)، والعبرية (`he`)، والكردية (`ku`)، والبشتو (`ps`)، والسندية (`sd`)، والأويغورية (`ug`)، والأردية (`ur`)، واليديشية (`yi`)، مع أي منطقة (`fa_IR` و`ur-PK`). وللقوالب المرفقة تسميات عربية وإنجليزية؛ أما اللغات الأخرى فتحتاج قالبًا فيه ملف `lang` خاص بها (انظر [قوالبك الخاصة](/ar/guide/custom-templates)).

لتحديد الاتجاه بنفسك أيًّا كانت اللغة:

```php
Doc::view('pdf.contract', $data)->locale('ar')->direction('ltr')->pdf();   // or ->ltr()
Doc::html($html)->rtl()->pdf();                                          // ->direction('rtl')
```

## الأرقام العربية أو اللاتينية {#numerals}

```php
Doc::template('invoice', $data)->locale('ar')->numerals('arabic')->pdf();   // ١٢٣
Doc::template('invoice', $data)->locale('ar')->numerals('latin')->pdf();    // 123
```

القيمة الافتراضية `latin`، ويحددها المفتاح `numerals` في ملف الإعدادات. غيّرها هناك للتطبيق كله:

```php
// config/easy-pdf-word.php
'numerals' => 'arabic',
```

- لا يتحول إلا النص. وتبقى الوسوم والسمات وأحجام CSS وألوانها وبيانات الصور والسكربتات كما هي، فيظل `width: 40mm` و`#0F766E` يعملان.
- تحتفظ عناوين البريد الإلكتروني والروابط بأرقامها: يبقى `info@biz2tech.com` و`https://example.com/i/1024` كما هما، وكذلك كيانات HTML.
- يتبع رأس الصفحة وتذييلها والعلامة المائية الإعداد نفسه. ومع mPDF تكون أرقام الصفحات عربية أيضًا، أما Chromium وGotenberg فيطبعان أرقام الصفحات بالأرقام اللاتينية.
- وفي ملفات Word تتبع الأرقام الإعداد كذلك.
- تقبل `->numerals()` أيضًا `arab` و`ar` و`eastern` و`hindi` للأرقام العربية، و`latn` و`en` و`western` للأرقام اللاتينية. وأي قيمة أخرى ترمي `Unknown numerals style [roman]. Use "latin" or "arabic".`
- مع `arabic` تتحول الأرقام اللاتينية والفارسية (۱۲۳) في بياناتك كلتاهما، فتخرج البيانات المختلطة بنمط واحد. ومع `latin` يبقى النص كما هو: الأرقام العربية الموجودة في بياناتك تبقى عربية.

## خلط العربية بالإنجليزية {#mixed-text}

في النص الذي يُكتب من اليمين إلى اليسار، تخرج القيمة المكونة من أرقام تفصلها مسافات أو شرطات بترتيب خاطئ: يظهر رقم الهاتف `+20 100 000 0000` هكذا `0000 000 100 20+`، والرقم الضريبي `123-456-789` هكذا `789-456-123`، والتاريخ `2026-10-08` هكذا `08-10-2026`. احفظ ترتيب هذه القيم بـ `$doc->ltr()` في Blade view:

```blade
<x-doc::layout :doc="$doc" title="عقد تقديم خدمات">
    <p>الهاتف: {{ $doc->ltr($customer['phone']) }}</p>
    <p>الرقم الضريبي: {{ $doc->ltr($customer['tax_number']) }}</p>
    <p>تاريخ البدء: {{ $doc->ltr('2026-10-08') }}</p>
</x-doc::layout>
```

تهرّب `$doc->ltr()` القيمة وتحيطها بالوسم `<bdo dir="ltr">`. استخدمها لأرقام الهواتف، والأرقام الضريبية وأرقام السجل التجاري، والتواريخ المكتوبة بشرطات. أما القيم التي تبدأ بحرف لاتيني (`INV-2026-1024`، ورقم IBAN، وعنوان البريد الإلكتروني)، والتواريخ المكتوبة بشرطات مائلة (`2026/10/08`)، والأرقام العادية (`1,250.00`) فتحتفظ بترتيبها دونها.

في مستند مبني بالكود، أعطِ النص النمط `ltr`:

```php
Doc::make()
    ->paragraph(['الهاتف: ', ['text' => '+20 100 000 0000', 'ltr' => true]])
    ->paragraph('123-456-789', ['ltr' => true])
    ->locale('ar')
    ->pdf();
```

الأرقام السالبة تُعالج عنك: `$doc->number(-2.3)` والأرقام في نصوص بناء المستند بالكود تُبقي علامة السالب في مقدمتها (`-2.30` لا `2.30-`). والقوالب المرفقة تحيط رموزها وأرقام هواتفها وأرقامها الضريبية بذلك مسبقًا. وتجد أدوات أخرى للـ views في [أدوات القوالب](/ar/reference/template-helpers)، وأنماط بناء المستند في [بناء المستند بالكود](/ar/guide/builder).

لمعرفة اتجاه نص ما، تنظر `Arabic::direction()` إلى أول حرف فيه، كما يفعل `dir="auto"` في المتصفح:

```php
use BiztechEG\EasyPdfWord\Arabic\Arabic;

Arabic::direction('فاتورة رقم 15');    // "rtl"
Arabic::direction('Invoice فاتورة');   // "ltr"
```

## التفقيط (المبلغ كتابةً) {#tafqeet}

```php
use BiztechEG\EasyPdfWord\Arabic\Arabic;

Arabic::tafqeet(1250.5, 'EGP');              // ألف ومائتان وخمسون جنيهاً وخمسون قرشاً
Arabic::tafqeet(3.03, 'SAR', only: true);    // فقط ثلاثة ريالات وثلاث هللات لا غير
Arabic::tafqeet(15750.5, 'QAR', only: true); // فقط خمسة عشر ألفاً وسبعمائة وخمسون ريالاً وخمسون درهماً لا غير
Arabic::tafqeet(2000000, 'USD');             // مليونا دولار
Arabic::tafqeet(123456);                     // مائة وثلاثة وعشرون ألفاً وأربعمائة وستة وخمسون
```

`Arabic::tafqeet($amount, $currency = null, $only = false)`:

- مع العملة يُقرأ المبلغ مالًا، بالصيغة النحوية الصحيحة للوحدة الأساسية والجزئية (ريالان، ثلاثة ريالات، أحد عشر ريالاً) وبالتذكير والتأنيث الصحيحين (ثلاث هللات).
- تحيط `only: true` النص بصيغة `فقط ... لا غير`، وهي الصيغة المعتادة في الفواتير والشيكات وسندات القبض.
- بدون عملة يُقرأ الرقم رقمًا، وتُقرأ الكسور بعد كلمة `فاصلة`: `Arabic::tafqeet(1.05)` تعطي `واحد فاصلة صفر خمسة`.
- يمكن أن يكون المبلغ رقمًا أو نصًا، بفواصل آلاف `,` أو بأرقام عربية: `'1,250.50'` و`'١٬٢٥٠٫٥٠'` كلاهما يعمل.
- المبالغ السالبة تبدأ بكلمة `سالب`: `Arabic::tafqeet(-250, 'EGP')` تعطي `سالب مائتان وخمسون جنيهاً`، و`-0.5` تعطي `سالب خمسون قرشاً`.
- تُقرَّب المبالغ إلى عدد الخانات العشرية للعملة، وتُقرأ حتى 999 تريليون.

العملات المضمنة:

| الرمز | الوحدة الأساسية | الوحدة الجزئية | الخانات العشرية |
| --- | --- | --- | --- |
| `EGP` | جنيه | قرش | 2 |
| `SAR` | ريال | هللة | 2 |
| `AED` | درهم | فلس | 2 |
| `QAR` | ريال | درهم | 2 |
| `KWD` | دينار | فلس | 3 |
| `USD` | دولار | سنت | 2 |
| `EUR` | يورو | سنت | 2 |

العملات ذات الخانات العشرية الثلاث تقرأ كسرها بالأجزاء من الألف: `Arabic::tafqeet(1.125, 'KWD')` تعطي `دينار واحد ومائة وخمسة وعشرون فلساً`.

والرمز غير المعروف يرمي `Unknown currency [GBP]. Register it with Tafqeet::registerCurrency().`

### إضافة عملة أو تعديلها {#currencies}

أضف العملات تحت `currencies` في `config/easy-pdf-word.php`. لكل وحدة صيغها العربية الأربع: المفرد، والمثنى، والجمع (من 3 إلى 10)، والمفرد المنصوب المستخدم من 11 إلى 99، ومعها جنسها (`m` للمذكر أو `f` للمؤنث). و`subunits` عدد الوحدات الجزئية في الوحدة الأساسية:

```php
'currencies' => [
    'OMR' => [
        'main' => ['forms' => ['ريال عماني', 'ريالان عمانيان', 'ريالات عمانية', 'ريالاً عمانياً'], 'gender' => 'm'],
        'sub' => ['forms' => ['بيسة', 'بيستان', 'بيسات', 'بيسة'], 'gender' => 'f'],
        'subunits' => 1000,
    ],
    'JOD' => [
        'main' => ['forms' => ['دينار', 'ديناران', 'دنانير', 'ديناراً'], 'gender' => 'm'],
        'sub' => ['forms' => ['فلس', 'فلسان', 'فلوس', 'فلساً'], 'gender' => 'm'],
        'subunits' => 1000,
    ],
],
```

```php
Arabic::tafqeet(12.5, 'OMR');   // اثنا عشر ريالاً عمانياً وخمسمائة بيسة
```

القيمة الافتراضية لـ `subunits` هي `100`، ولـ `gender` هي `m`. والرمز المضمن أصلًا، مثل `SAR`، يُستبدل بتعريفك. ويمكنك أيضًا تسجيل عملة في الكود بـ `BiztechEG\EasyPdfWord\Arabic\Tafqeet::registerCurrency('OMR', [...])`.

وفي القوالب، تتعامل `$doc->tafqeet()` أيضًا مع العملات غير المسجلة، فتقرأ الرقم وتضيف الرمز: `فقط مائة وخمسون GBP و25/100 لا غير`. انظر [أدوات القوالب](/ar/reference/template-helpers).

## التاريخ الهجري {#hijri}

```php
use BiztechEG\EasyPdfWord\Arabic\Arabic;

Arabic::hijri('2026-10-08');                       // ٢٧ ربيع الآخر ١٤٤٨ هـ
Arabic::hijri('2026-10-08', numerals: 'latin');    // 27 ربيع الآخر 1448 هـ
Arabic::hijri('2026-10-08', 'EEEE d MMMM y');      // الخميس ٢٧ ربيع الآخر ١٤٤٨ هـ
Arabic::hijri('2026-10-08', 'd/M/y', 'latin');     // 27/4/1448 هـ
Arabic::hijri();                                   // اليوم
```

`Arabic::hijri($date = null, $pattern = 'd MMMM y', $numerals = 'arabic')`:

- تتبع التواريخ تقويم أم القرى المعتمد في السعودية.
- `$date` كائن `Carbon` أو `DateTime`، أو نص تاريخ (`'2026-10-08'` و`'2026-10-08T10:30:00Z'`)، أو طابع زمني (timestamp). وتُستخدم المنطقة الزمنية للتاريخ نفسه.
- `$pattern` نمط تاريخ بصيغة ICU: `d` اليوم، و`M` رقم الشهر، و`MMMM` اسم الشهر، و`y` السنة، و`EEEE` اسم اليوم.
- تُضاف `هـ` في النهاية.

للحصول على السنة والشهر واليوم أرقامًا، استخدم الصنف `Hijri`:

```php
use BiztechEG\EasyPdfWord\Arabic\Hijri;

Hijri::parts('2026-10-08');   // ['year' => 1448, 'month' => 4, 'day' => 27]
Hijri::format('2026-10-08', 'd MMMM y', 'latin', suffix: false);   // 27 ربيع الآخر 1448
```

يحتاج التاريخ الهجري إلى إضافة `intl` في PHP. وبدونها ترمي `Arabic::hijri()` الرسالة `Hijri dates need the PHP intl extension.`، وتحذف القوالب المرفقة التاريخ الهجري بدلًا من أن تفشل.

## الأرقام العربية في أي مكان {#arabic-numerals}

تحوّل `Arabic::numerals()` أرقام أي قيمة:

```php
Arabic::numerals('2026');                // ٢٠٢٦
Arabic::numerals('12,500.75');           // ١٢٬٥٠٠٫٧٥
Arabic::numerals('١٢٣', 'latin');        // 123
```

وتستخدم الفاصلة العشرية العربية وفاصل الآلاف العربي (٫ ٬). وللتحويل بدونهما استخدم `BiztechEG\EasyPdfWord\Arabic\Numerals::toArabic('12,500.75', separators: false)`، التي تعطي `١٢,٥٠٠.٧٥`.

## الدوال العامة وتوجيهات Blade {#helpers}

الأدوات نفسها متاحة دوالًا عامة:

```php
tafqeet(1250.5, 'EGP');                   // ألف ومائتان وخمسون جنيهاً وخمسون قرشاً
tafqeet(1250.5, 'EGP', true);             // فقط ألف ومائتان وخمسون جنيهاً وخمسون قرشاً لا غير
hijri_date('2026-10-08');                 // ٢٧ ربيع الآخر ١٤٤٨ هـ
hijri_date('2026-10-08', numerals: 'latin');
arabic_numerals(2026);                    // ٢٠٢٦
```

وتوجيهات Blade (directives) في أي view، بما فيها رسائل البريد وصفحات الموقع:

```blade
<p>المبلغ: @tafqeet($payment->amount, 'SAR', true)</p>
<p>التاريخ: @hijri($payment->paid_at)</p>
```

تهرّب التوجيهات مخرجاتها. ولا تُعرَّف كل دالة إلا إن لم يكن في تطبيقك دالة بالاسم نفسه.

## الفواصل العربية والخطوط {#separators}

مع الأرقام العربية، يمكن أن تستخدم الأرقام في المستند الفاصلة العشرية العربية `٫` وفاصل الآلاف العربي `٬` (١٢٬٥٠٠٫٧٥)، أو أن تحتفظ بـ `.` و`,` (١٢,٥٠٠.٧٥). ويتوقف ذلك على الخط، لأن بعض الخطوط لا ترسمهما بوضوح:

| الخط | الفواصل مع الأرقام العربية |
| --- | --- |
| Noto Naskh Arabic (`naskh`) | ٫ و٬ |
| Cairo (`cairo`، الافتراضي) | `.` و`,`: يرسم Cairo الفاصلتين العربيتين كلتيهما مثل الفاصلة |
| Tajawal (`tajawal`) | `.` و`,`: لا يحتوي Tajawal الفاصلتين العربيتين |
| خطوطك الخاصة | `.` و`,`، إلا إن سجلتها مع `'arabic_separators' => true` |
| ملفات Word | `.` و`,` أيًّا كان الخط، لأن Word يستخدم خطوط القارئ |

```php
Doc::template('invoice', $data)->locale('ar')->numerals('arabic')->font('naskh')->pdf();   // ١٢٬٥٠٠٫٧٥
Doc::template('invoice', $data)->locale('ar')->numerals('arabic')->pdf();                  // ١٢,٥٠٠.٧٥
```

تشرح صفحة [الخطوط](/ar/guide/fonts#custom-fonts) تسجيل خطوطك الخاصة.
