# الفاتورة الضريبية

قالب `invoice` هو الفاتورة الضريبية التي يصدرها البائع للمشتري: الأصناف والخصومات وضريبة القيمة المضافة والإجمالي بالأرقام والتفقيط، مع رمز QR اختياري. يناسب الفواتير المصرية (ضريبة 14%، وهي القيمة الافتراضية) والفواتير الضريبية المبسطة في السعودية مع رمز QR لهيئة الزكاة والضريبة والجمارك (ضريبة 15%).

## متى تستخدمه {#when-to-use}

- شركة برمجيات في القاهرة تُصدر فاتورة لعميل عن مشروع واشتراك استضافة وأيام تدريب، مع ضريبة 14%.
- متجر في الرياض يطبع فاتورة ضريبية مبسطة برمز QR لهيئة الزكاة عند الكاشير، أو يرفقها برسالة تأكيد الطلب.
- شركة مسجلة في منظومة الفاتورة الإلكترونية المصرية تحتفظ بتصميم فاتورتها، مع الرقم الإلكتروني للفاتورة ورمز QR يفتحها على البوابة.
- موزع في الكويت أو الإمارات يُصدر فواتيره بالدينار أو الدرهم، وتحتفظ المبالغ بعدد خانات العملة العشرية (ثلاث للدينار الكويتي).
- قسم الحسابات لدى العميل يطلب الفاتورة ملف Word ليختمها أو يعدّلها.

## مثال سريع {#example}

هذا الكود يبني الفاتورة التي في المعاينة أعلاه ويحفظها ملف PDF وملف Word:

```php
use BiztechEG\EasyPdfWord\Facades\Doc;

$invoice = Doc::template('invoice', [
    'invoice' => [
        'number' => 'INV-2026-1024',
        'date' => '2026-10-08',
        'due_date' => '2026-10-22',
        'currency' => 'EGP',
        'tax_rate' => 14,
        'notes' => 'يرجى التحويل على الحساب البنكي خلال 14 يوماً من تاريخ الفاتورة.',
    ],
    'seller' => [
        'name' => 'شركة بيزتك للحلول البرمجية',
        'address' => '15 شارع التحرير، الدقي، الجيزة',
        'tax_number' => '123-456-789',
        'phone' => '+20 100 000 0000',
    ],
    'buyer' => [
        'name' => 'مؤسسة النور للتجارة',
        'address' => 'مدينة نصر، القاهرة',
        'tax_number' => '987-654-321',
    ],
    'items' => [
        ['description' => 'تطوير نظام إدارة المخزون (Laravel)', 'quantity' => 1, 'unit_price' => 25000],
        ['description' => 'استضافة سحابية - اشتراك سنوي', 'quantity' => 12, 'unit_price' => 450, 'discount' => 400],
        ['description' => 'تدريب فريق العمل', 'quantity' => 3, 'unit_price' => 1500],
    ],
    'qr' => 'https://example.com/invoices/INV-2026-1024',
])->locale('ar');

// ملف PDF
$invoice->pdf()->save(storage_path('app/invoices/INV-2026-1024.pdf'));

// الفاتورة نفسها ملف Word
$invoice->word()->save(storage_path('app/invoices/INV-2026-1024.docx'));
```

تعرض الفاتورة مجموعاً فرعياً قدره 34,900.00 وخصماً قدره ‎-400.00 وضريبة (14%) قدرها 4,830.00 وإجمالياً مستحقاً قدره 39,330.00 ج.م، يليه «فقط تسعة وثلاثون ألفاً وثلاثمائة وثلاثون جنيهاً لا غير». وتحت تاريخ الإصدار يظهر التاريخ الهجري: 27 ربيع الآخر 1448 هـ.

وفي الـ controller أرجِع الملف بدلاً من حفظه:

```php
return $invoice->pdf()->download('INV-2026-1024.pdf');
```

استخدم `->stream()` لعرضه في المتصفح، و `->save('invoices/INV-2026-1024.pdf', disk: 's3')` لحفظه على disk. انظر [الإخراج والتسليم](/ar/guide/output).

::: tip بيانات من الـ models
تُقبل الـ collections والـ models في أي مكان ينتظر مصفوفة، فيمكن أن تأتي الأصناف من الطلب مباشرة:

```php
'items' => $order->lines->map(fn ($line) => [
    'description' => $line->name,
    'quantity' => $line->qty,
    'unit_price' => $line->price,
]),
```
:::

## الحقول {#fields}

| الحقل | إلزامي | النوع / القيم | القيمة الافتراضية | الوظيفة |
| --- | --- | --- | --- | --- |
| `invoice.number` | نعم | نص أو رقم | | رقم الفاتورة، أعلى الصفحة وفي تذييل الصفحة. يُكتب من اليسار إلى اليمين داخل النص العربي. |
| `invoice.date` | نعم | تاريخ (نص أو Carbon) | | تاريخ الإصدار، ويُطبع بالشكل `2026/10/08`. ومنه يُحسب التاريخ الهجري ووقت رمز QR لهيئة الزكاة. |
| `invoice.due_date` | لا | تاريخ | | تاريخ الاستحقاق، ويُطبع تحت تاريخ الإصدار إن وُجد. |
| `invoice.currency` | نعم | رمز من 3 أحرف | `EGP` | عملة كل المبالغ: عدد خاناتها العشرية (3 للدينار الكويتي والبحريني والعماني والأردني)، والاختصار بعد الإجمالي (ج.م، ر.س، د.ك ... بالعربية، والرمز بالإنجليزية)، والتفقيط. |
| `invoice.tax_rate` | لا | رقم، صفر أو أكثر | `14` | نسبة ضريبة القيمة المضافة، وتُحسب على المجموع بعد الخصم. سطر الضريبة يظهر دائماً، حتى عند 0%. |
| `invoice.notes` | لا | نص | | ملاحظات في آخر الفاتورة. |
| `invoice.eta_uuid` | لا | نص | | الرقم الإلكتروني للفاتورة في المنظومة المصرية، ويُطبع بخط صغير تحت رمز QR. لا يظهر إلا مع رمز QR. |
| `seller` | لا | مصفوفة | `company` في الهوية | البائع. كل مفتاح تمرره يحل محل المفتاح نفسه في بيانات الشركة في الهوية، وتُهمل القيم الفارغة. المفاتيح المقروءة: `name` و `address` و `phone` و `tax_number` و `commercial_register`. |
| `buyer.name` | نعم | نص | | اسم العميل في خانة «العميل». |
| `buyer.address` | لا | نص | | عنوان العميل. |
| `buyer.tax_number` | لا | نص | | الرقم الضريبي للعميل. |
| `items` | نعم | مصفوفة، عنصر واحد على الأقل | | أسطر الفاتورة، مرقمة 1، 2، 3 بترتيبها. |
| `items.*.description` | نعم | نص | | ما بيع. |
| `items.*.quantity` | نعم | رقم | | الكمية الصحيحة تُطبع بلا كسور، وغيرها بخانتين. |
| `items.*.unit_price` | نعم | رقم | | سعر الوحدة قبل الضريبة. |
| `items.*.discount` | لا | رقم، صفر أو أكثر | | مبلغ (لا نسبة) يُخصم من هذا السطر، ولا يزيد على الكمية × سعر الوحدة. |
| `qr` | لا | نص | `null` | القيمة `'zatca'` تبني رمز QR لهيئة الزكاة من بيانات الفاتورة؛ وأي نص آخر (رابط أو رقم) يوضع في الرمز كما هو؛ و `null` بلا رمز. |

الحقل الذي له قيمة افتراضية يُملأ قبل التحقق من البيانات، فيمكنك تركه حتى لو كان إلزامياً.

### القيم المحسوبة {#computed}

تضيف خطوة `prepare()` في القالب هذه القيم إلى البيانات قبل الرسم:

| القيمة | طريقة حسابها |
| --- | --- |
| `items.*.total` | الكمية × سعر الوحدة، مقربة لخانات العملة، ناقص خصم السطر |
| `totals.subtotal` | مجموع الكمية × سعر الوحدة في كل الأسطر |
| `totals.discount` | مجموع خصومات الأسطر (يُطبع سطراً سالباً إن كان أكبر من صفر) |
| `totals.taxable` | المجموع الفرعي ناقص الخصم |
| `totals.tax` | الخاضع للضريبة × `tax_rate` / 100، مقرباً |
| `totals.total` | الخاضع للضريبة مع الضريبة: «الإجمالي المستحق» |
| `seller` | بيانات الشركة في الهوية مدموجة مع `seller` الذي مررته |
| `qr` | مع `'zatca'` تُستبدل بمحتوى رمز هيئة الزكاة بترميز base64 |

يُقرَّب كل سطر على حدة، فيساوي مجموع الأسطر المجموع الفرعي دائماً. ومع `Doc::fake()` يمكنك فحص هذه القيم في الاختبارات بـ `$doc->data('totals.total')`؛ انظر [اختبار تطبيقك](/ar/guide/testing).

ويطبع القالب في الصفحة أيضاً:

- **التفقيط** (المبلغ بالحروف) من `totals.total` والعملة، بلغة المستند.
- **التاريخ الهجري** لـ `invoice.date`، في المستندات العربية عندما تكون إضافة `intl` في PHP مثبتة.

### قيم الهوية {#theme}

| مفتاح الهوية | استخدامه |
| --- | --- |
| `company.name` و `company.address` و `company.phone` و `company.tax_number` | بيانات البائع الافتراضية (وأي مفتاح آخر تضيفه إلى `company`، مثل `commercial_register`، يُدمج أيضاً) |
| `logo` | فوق اسم البائع أعلى الصفحة |
| `primary` | اسم البائع والعنوان ورأس الجدول وسطر «الإجمالي المستحق» والإطار حول التفقيط |
| `muted` | العناوين الصغيرة والملاحظات |
| `border` | خانتا البائع والعميل والخطوط بين الأصناف |
| `text` | لون النص |

## الأشكال والخيارات {#options}

### رمز هيئة الزكاة، أو رابط، أو بلا رمز {#qr}

اجعل `qr` بالقيمة `'zatca'` فيبني القالب رمز QR للمرحلة الأولى في السعودية من الفاتورة نفسها: اسم البائع، ورقمه الضريبي (`seller.tax_number`)، ووقت الفاتورة، والإجمالي شاملاً الضريبة، ومبلغ الضريبة.

```php
$invoice = Doc::template('invoice', [
    'invoice' => [
        'number' => 'SA-2026-0451',
        'date' => '2026-10-08 14:30',
        'currency' => 'SAR',
        'tax_rate' => 15,
    ],
    'seller' => [
        'name' => 'مؤسسة النور للتجارة',
        'address' => 'حي العليا، الرياض',
        'tax_number' => '300000000000003',
        'commercial_register' => '1010123456',
    ],
    'buyer' => ['name' => 'شركة الأفق للمقاولات'],
    'items' => [
        ['description' => 'اشتراك سنوي في نظام نقاط البيع', 'quantity' => 1, 'unit_price' => 1000],
    ],
    'qr' => 'zatca',
])->locale('ar');
```

يحمل الرمز القيم `مؤسسة النور للتجارة` و `300000000000003` و `2026-10-08T14:30:00Z` و `1150.00` و `150.00`. يُكتب الوقت بتوقيت UTC: التاريخ مع وقت (أو `now()`) يُقرأ بالمنطقة الزمنية لتطبيقك ثم يُحوَّل، والتاريخ وحده يُعد منتصف ليل ذلك اليوم بتوقيت UTC. ويمكن أن يأتي البائع من بيانات الشركة في الهوية ما دام فيها `tax_number`.

لا يحمل الرمز إلا هذه الحقول الخمسة. المكتبة لا توقّع الفواتير ولا ترسلها إلى هيئة الزكاة. انظر [فاتورة هيئة الزكاة السعودية](/ar/recipes/zatca-invoice) للحالة كاملة.

أي نص آخر يوضع في الرمز كما هو. لفاتورة أُرسلت إلى منظومة الفاتورة الإلكترونية المصرية، ضع رابط البوابة في الرمز والرقم الإلكتروني تحته:

```php
'invoice' => [
    // ...
    'eta_uuid' => 'R6ZQ4SB1ZWP2XKCV2G0AYXHG10',
],
'qr' => 'https://invoicing.eta.gov.eg/documents/R6ZQ4SB1ZWP2XKCV2G0AYXHG10/share/A3MZ7X0NE6C8XH3GV2G0AYXHG10QN3K91653372781',
```

اترك `qr` (أو اجعله `null`) لفاتورة بلا رمز. ولا يُطبع `invoice.eta_uuid` إلا بجوار رمز. وللمستند الكامل لمصلحة الضرائب المصرية، بأرقام التسجيل الضريبي وأنواع الضرائب، استخدم قالب [الفاتورة الإلكترونية المصرية](/ar/templates/eg-invoice).

### التاريخ الهجري والتفقيط {#arabic}

- تعرض المستندات العربية (`->locale('ar')`، أو أي لغة من اليمين إلى اليسار) التاريخ الهجري لـ `invoice.date` تحت تاريخ الإصدار، مثل 27 ربيع الآخر 1448 هـ. يحتاج إضافة `intl` في PHP، وبدونها يُحذف السطر.
- يُطبع المبلغ بالحروف تحت الإجماليات بلغة المستند. وهو بالعربية التفقيط، مثل «فقط ألف ومائة وخمسون ريالاً لا غير»: تُقرأ عملات EGP و SAR و AED و QAR و KWD و USD و EUR بأسمائها العربية، وتضيف غيرها تحت `currencies` في الإعدادات (انظر [دعم اللغة العربية](/ar/guide/arabic))، والعملة غير المعروفة يُقرأ رقمها بالحروف متبوعاً برمزها. وبالإنجليزية تكتب إضافة `intl` في PHP الرقم بالكلمات («one thousand one hundred fifty SAR only»)، وبدونها يُحذف هذا السطر من المستندات الإنجليزية.

### الأرقام العربية والألوان وبيانات شركتك {#branding}

اضبط البائع مرة واحدة في الهوية، فلا تحتاج الفاتورة إلا العميل والأصناف. ويظهر هنا عمل القيم الافتراضية أيضاً: الجنيه المصري وضريبة 14%.

```php
$invoice = Doc::template('invoice', [
    'invoice' => ['number' => 'INV-2026-1025', 'date' => '2026-10-09'],
    'buyer' => ['name' => 'مؤسسة النور للتجارة'],
    'items' => [
        ['description' => 'صيانة شهرية للنظام', 'quantity' => 1, 'unit_price' => 3000],
    ],
])
    ->theme([
        'primary' => '#1D4ED8',
        'logo' => public_path('images/logo.png'),
        'company' => [
            'name' => 'شركة بيزتك للحلول البرمجية',
            'address' => '15 شارع التحرير، الدقي، الجيزة',
            'tax_number' => '123-456-789',
        ],
    ])
    ->locale('ar')
    ->numerals('arabic');
```

يُطبع الإجمالي ٣,٤٢٠.٠٠ ج.م بالأرقام العربية. ولاستخدام الشركة نفسها في كل المستندات، ضع هذه القيم تحت `theme` في `config/easy-pdf-word.php`؛ وتشرح صفحة [الصور](/ar/guide/images) مسارات الشعار المسموح بها.

### قواعد تستحق المعرفة {#rules}

- خصم السطر الأكبر من قيمة السطر يرمي `ValidationException` على الحقل `items.N.discount`.
- كل مبلغ يُقرَّب لخانات العملة العشرية: خانتان لمعظم العملات، وثلاث للدينار الكويتي والبحريني والعماني والأردني.
- عمود الخصم يظهر دائماً، وفيه `-` للأسطر التي بلا خصم.

## ملف Word {#word}

نسخة Word تأتي من ملف `word.php` في القالب، وتُبنى من البيانات المحسوبة نفسها؛ أما PDF فيأتي من `pdf.html.php`. يعرض الاثنان المعلومات نفسها، مع فروق قليلة في التخطيط:

- مع وجود شعار، يأخذ الشعار الركن العلوي، ويأتي اسم البائع وعنوانه وهاتفه تحت رأس الفاتورة.
- تكرر خانة البائع عنوانه أيضاً.
- يأتي رمز QR تحت الإجماليات لا بجوارها.
- إطار التفقيط متصل (ومتقطع في PDF).
- يحتفظ تذييل الصفحة برقم الفاتورة و«صفحة X من Y» بحقول أرقام صفحات Word.

ملف Word بلا علامة مائية، ويرفض `->word()` أي مستند عليه `->password()`. ملفات Word تحتاج الحزمة `phpoffice/phpword` وتستخدم الخط المضبوط في `DOC_WORD_FONT` (Arial افتراضياً)؛ انظر [ملفات Word](/ar/guide/word).

## خصّصه {#customise}

```bash
php artisan doc:template invoice --as=my-invoice
```

ينسخ هذا الأمر القالب إلى `resources/doc-templates/my-invoice`. استخدمه بـ `Doc::template('my-invoice', $data)` وعدّل:

- `lang/ar.php` و `lang/en.php` للعناوين، مثل عنوان الفاتورة أو اختصارات العملات.
- `template.php` للحقول والقيم الافتراضية `defaults` (مثلاً `'invoice' => ['currency' => 'SAR', 'tax_rate' => 15]` للسعودية) والإجماليات في `prepare()`.
- `pdf.html.php` لتخطيط PDF و `word.php` لتخطيط Word. عدّل الاثنين عندما تنقل شيئاً أو تضيفه.
- `footer.html.php` لتذييل الصفحة؛ يصبح `{page}` و `{pages}` أرقام الصفحات.

انظر [قوالبك الخاصة](/ar/guide/custom-templates) لمحتويات المجلد والأدوات المتاحة داخل القالب.
